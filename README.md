# Detonate

Competitive Minesweeper. **Don't.**

Clear every safe cell. The first click is safe. Detonating ends the run.

The game you can play today is local and unranked. Accounts, verified runs, daily boards, and leaderboards are the next layer; they are not in the product yet.

## What you can do now

- Play in the browser with no account and no API.
- Choose **Beginner** (9×9, 10 mines), **Intermediate** (16×16, 40 mines), or **Expert** (30×16, 99 mines).
- Reveal a cell, flag a cell (right-click), or chord a numbered cell when the surrounding flags match its count.
- See remaining mines, a timer, and the board seed.
- Deal a new board. Each deal uses a new seed; the same seed produces the same mine layout.
- First click (and its neighbors, when the board has room) is guaranteed safe. Mines are placed only after that click.
- Win by revealing every safe cell. Lose by revealing a mine. A win flags the remaining mines; a loss reveals them.

## Planned

These are named in the codebase and are not shipped. Move an item into **What you can do now** only when it actually works.

- **Verified runs.** Replay a sequence of reveal, flag, and chord events so a result can be checked against the engine.
- **Daily board.** One shared seed per day, generated by the worker.
- **Ranked play and leaderboards.** Submit a verified run and compare times. The UI will call the API through `NEXT_PUBLIC_API_URL`.
- **Accounts.** Identity for ranked runs. Not designed yet beyond that need.

## How it is built

Two apps, deployed separately. Play does not call the API.

| Folder | What it is | Run |
| --- | --- | --- |
| [`frontend/`](frontend/) | Next.js UI and the TypeScript engine | See [`frontend/README.md`](frontend/README.md) |
| [`backend/`](backend/) | FastAPI, worker stub, and the Python engine | See [`backend/README.md`](backend/README.md) |

The Python engine in `backend/packages/engine` is the source of truth. The TypeScript port in `frontend/packages/engine` is checked against the same JSON fixtures. After a rules change, export fixtures from the backend (steps in [`backend/README.md`](backend/README.md)), then run the frontend engine tests.

The API today exposes health, readiness (Postgres and Redis), and the difficulty list. It does not store games or scores. Postgres and Redis are optional until ranked features need them. The worker process prints a placeholder and does not schedule a daily board yet.
